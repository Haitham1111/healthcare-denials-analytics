# Healthcare Denials Analytics

**Which payers deny, why, and where appeals pay off.** SQL Server (T-SQL) + Power BI.

> **Data notice: every row is synthetic.** `data/claims.csv` is generated by
> `data/generate_synthetic_data.py` (seeded, reproducible). It is modeled on real
> behavioral-health revenue-cycle workflows, but no real patient, payer, provider, or
> employer data is used. All six payer names are fictional. CMS public files (DE-SynPUF)
> have no claim-level denial reasons, CARC codes, or appeal outcomes, so a labeled
> synthetic set is the honest choice.

## 1. Business Problem & Executive Summary

Every denied claim is lost revenue until proven otherwise. A denials team has to answer:
**which payer** denies us, **why** (in CARC terms the billing team can act on), and
**is the appeal worth the labor?**

Headline findings (4,200 claims, 1,198 denied = 28.5%, $719,233 billed):

1. **Two payers drive the problem.** Liberty Care PPO denies **42.5%** (324 of 763);
   Pinnacle Commercial Plan **39.8%**. The other four sit between 12.9% and 27.5%.
2. **Liberty's weapon is CO-50 (medical necessity).** 58.3% of its denials are CO-50, and
   **100% of its denied 60-minute therapy sessions (CPT 90837)** (66 of 66). Fix: stronger
   documentation for 90837, or a payer escalation.
3. **Pinnacle's problem is benefit design.** 48.0% of its denials are **CO-96 non-covered
   charges**. Fix upstream: verify benefits and get authorizations before service.
4. **Appeals pay, selectively.** Summit overturns **76.9%** of decided appeals (appeal
   everything). Apex overturns **33.3%** (be selective). Blended: 55.5% (309 of 557).
5. **$150,135 billed revenue is at risk** across 889 denied claims (upheld, pending, or never
   appealed). Liberty alone: $42,492 (28.3%).
6. **Denials rot in AR.** Liberty's denied claims average **86.6 days** in AR vs 28.8 paid,
   about 3x. Every payer shows the same pattern.

## 2. Data Architecture & Relational Schema

- **Source:** one flat, claim-level table, `dbo.claims`, in database `Healthcare_Denials`
  (SQL Server Express). Loaded from `data/claims.csv` with `BULK INSERT`
  ([`sql/00_setup_database.sql`](sql/00_setup_database.sql)). No joins: each row is one claim.
- **Columns:** `claim_id, payer_name, cpt_code, diagnosis_code, billed_amount, claim_status,
  denial_reason, denial_date, appeal_filed, appeal_outcome, days_in_ar, service_date`
- **Scale:** 4,200 claims, 6 payers, 8 CPT codes, service dates 2025-01-06 to 2025-09-13.
- **Denial reasons:** CARC-style codes (CO-50, CO-96, CO-97, CO-29, ...).
- **Appeal outcomes:** overturned / upheld / pending / not appealed. Overturn rate uses decided
  appeals only.
- **Built-in story:** six payers with distinct behavior: two aggressive deniers, one low-denier
  whose appeals rarely win, one where appeals almost always win.
- **Flow:** `claims.csv` -> SQL Server `dbo.claims` -> T-SQL analysis queries + Power BI
  (Power Query -> DAX measures -> custom dark theme). Dashboard numbers reconcile to the SQL
  output. Definitions: [`reports/dax-measures.md`](reports/dax-measures.md).

## 5. How to Download and Run

**Dashboard (Power BI)**
1. Download [`healthcare-denials-dashboard.pbix`](healthcare-denials-dashboard.pbix)
   (on GitHub: open the file, click *Download raw file*, or clone the repo).
2. Open it in **Power BI Desktop** (Windows). It reads `dbo.claims` from SQL Server, so load
   the database first (below), then *Refresh*. If your server differs from `.\SQLEXPRESS`,
   change it under *Transform data > Data source settings*.

**SQL (SQL Server Express / SSMS)**
1. Run [`sql/00_setup_database.sql`](sql/00_setup_database.sql) on `.\SQLEXPRESS`. It creates
   `Healthcare_Denials`, the `dbo.claims` table, and loads `data/claims.csv` with `BULK INSERT`
   (edit the file path at the top if your copy lives elsewhere; the SQL Server service account
   needs read access). Expect 4,200 claims, 1,198 denied.
2. Run `sql/01` to `sql/06` against `Healthcare_Denials`.

**Regenerate the data:** `python data/generate_synthetic_data.py` (seed 42).

**Repo layout:** `data/` (CSV + generator), `sql/` (queries, `results/` screenshots),
`reports/` (DAX/Power Query doc, themes, dashboard screenshots), the `.pbix` at root.

## Next Steps with Real Data

- **Join eligibility data** to separate true CO-96 (benefit exclusion) from
  registration errors (wrong member ID, terminated coverage) — different
  owners, different fixes.
- **Track denial reason *shifts* per payer per month** — payers change
  adjudication behavior silently; a 5-point jump in CO-50 from one payer is
  an early warning worth a same-week call to the provider rep.
- **Model appeal ROI per payer**: (overturn rate × average recovery) −
  (staff minutes × cost). Stop appealing payers below the line; reassign
  that labor to clean-claim submission.
- **Add timely-filing deadline math** (CO-29): every denial gets a
  days-remaining-to-file-appeal clock so nothing dies on a technicality.

## Limitations

- Synthetic data. Patterns (payer personalities, appeal win rates) are built in by the
  generator, so findings demonstrate method, not real-world payer behavior.
- Single flat table: no eligibility, remittance, or provider dimensions.
- Revenue at risk uses billed amounts, not expected or allowed amounts.
- Window is Jan-Sep 2025; days in AR for unresolved claims is measured to the day it was calculated.
